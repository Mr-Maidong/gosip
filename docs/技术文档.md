## 1. 项目概述

### 1.1 项目简介

**GoSIP** 是一个基于 Go 语言开发的 GB28181 SIP 服务器，专门用于视频监控领域的信令控制。该项目与 [ZLMediaKit](https://github.com/xia-chu/ZLMediaKit) 媒体服务器配合使用，提供完整的 GB28181 国标协议支持。

### 1.2 主要功能

| 功能模块 | 功能描述 | 状态 |
|----------|----------|------|
| 设备管理 | NVR/DVR/IPC 摄像头注册、注销、心跳 | ✅ |
| 通道管理 | 摄像头通道信息同步和管理 | ✅ |
| 实时预览 | 直播流拉取和播放 | ✅ |
| 远程回放 | 录像回放功能 | ✅ |
| 录像查询 | 获取设备录像历史文件 | ✅ |
| 流管理 | 直播流转码、存储、服务重启恢复 | ✅ |
| 语音对讲 | 双向音频通话 | ✅ |
| PTZ控制 | 云台控制（方向、变倍、光圈、聚焦） | ✅ |
| 用户管理 | 用户 CRUD、启用/禁用、密码修改 | ✅ |
| 权限管理 | RBAC 三层权限模型（用户-角色-权限） | ✅ |
| JWT认证 | Token 有效期 7 天 | ✅ |
| Webhook通知 | 异步事件通知 | ✅ |

### 1.3 版本信息

- **Go 版本**: 1.19+
- **数据库**: MySQL
- **媒体服务器**: ZLMediaKit

## 5. 核心模块详解

### 5.1 主程序入口 (main.go)

```go
// 主要职责:
// 1. 加载配置文件
// 2. 初始化数据库连接
// 3. 初始化 SIP 服务器
// 4. 初始化 HTTP API 服务
// 5. 启动定时任务
// 6. 注册优雅关闭
```

**启动流程**:

1. `m.LoadConfig()` - 加载配置文件
2. `db.Open()` - 打开数据库连接
3. `sipapi.Init()` - 初始化 SIP 服务器
4. `api.Init()` - 初始化 HTTP 路由
5. 启动 cron 定时任务
6. 启动 HTTP 服务器

### 5.2 SIP 服务器模块 (sip/)

#### 5.2.1 设备注册/注销 (devices.go)

**核心数据结构**:

```go
type Devices struct {
    db.DBModel
    Name       string // 设备名称
    DeviceID   string // 设备ID (唯一标识)
    Region     string // 设备域
    Host       string // Via 地址
    Port       string // Via 端口
    TransPort  string // 传输协议 (UDP/TCP)
    Proto      string // 协议类型
    Manufacturer string // 厂商
    DeviceType string // 设备类型
    Firmware   string // 固件版本
    Model      string // 型号
    PWD        string // 认证密码
    Regist     bool   // 注册状态
    ActiveAt   int64  // 最后活跃时间
}
```

**处理流程**:

```
设备发送 REGISTER → 解析设备信息 → 验证密码 → 更新数据库 → 返回 200 OK
```

#### 5.2.2 通道管理 (devices.go)

**核心数据结构**:

```go
type Channels struct {
    db.DBModel
    ChannelID   string // 通道编码 (唯一标识)
    DeviceID    string // 所属设备ID
    Name        string // 通道名称
    MeMo        string // 备注
    Manufacturer string // 厂商
    Model       string // 型号
    Address     string // IP地址
    Status      string // 在线状态 (ON/OFF)
    VF          string // 视频格式 (H264/H265)
    Height      int    // 视频高度
    Width       int    // 视频宽度
    FPS         int    // 帧率
    StreamType  string // 流类型 (push/pull)
    URL         string // 拉流地址
    Active      int64  // 最后活跃时间
}
```

**通道同步流程**:

```
API 请求同步 → 发送 Catalog 请求 → 设备返回通道列表 → 解析并更新数据库
```

#### 5.2.3 播放控制 (play.go)

**播放类型**:

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| push | 设备主动推流 | 大多数 IPC/NVR |
| pull | 服务端拉流 | 非 GB28181 设备 |

**播放流程**:

```
1. API 调用 /api/v1/channels/{id}/streams
2. 检查设备是否在线
3. 创建 ZLM RTP 服务器 (openRtpServer)
4. 发送 INVITE 请求到设备
5. 设备推送 RTP 流到 ZLM
6. 返回播放地址 (RTMP/HLS/FLV)
```

**停止播放流程**:

```
1. API 调用 DELETE /api/v1/streams/{id}
2. 关闭 ZLM RTP 服务器 (closeRtpServer)
3. 发送 BYE 请求到设备
4. 更新流状态
```

### 5.3 流管理 (stream.go)

**Streams 数据结构**:

```go
type Streams struct {
    db.DBModel
    T          int    // 0=直播, 1=历史回放
    DeviceID   string // 设备ID
    ChannelID  string // 通道ID
    StreamType string // push/pull
    Status     int    // 0=正常, 1=关闭, -1=未开始
    StreamID   string // 流ID (GB28181 SSRC)
    CallID     string // SIP Call-ID
    HTTP       string // HLS 地址
    RTMP       string // RTMP 地址
    RTSP       string // RTSP 地址
    WSFLV      string // WebSocket FLV 地址
    Stream     bool   // ZLM 是否收到流
}
```

**流检查定时任务**:

- 每 5 分钟执行 `CheckStreams()`
- 检查流是否超时或失效
- 自动关闭无效流

### 5.4 语音对讲 (talk.go)

**对讲流程**:

```
1. API 调用 /api/v1/channels/{id}/start_talk
2. 开启 ZLM RTP 服务器 (startSendRtpPassive)
3. 发送 INVITE 请求 (audio only)
4. 设备返回 SDP
5. 开始双向音频传输
```

**对讲协议**:

| 参数 | 值 | 说明 |
|------|-----|------|
| 音频格式 | PCMA/8000 | G.711 A律 |
| 传输协议 | TCP/RTP/AVP | RTP over TCP |
| 模式 | sendonly | 发送模式 |

### 5.5 PTZ 云台控制 (devices.go)

**PTZ 控制类型**:

| 类型 | 命令码 | 说明 |
|------|--------|------|
| halt | 0x0F00 | 停止 |
| up | 0x0800 | 上 |
| down | 0x0400 | 下 |
| left | 0x0200 | 左 |
| right | 0x0100 | 右 |
| zoom_in | 0x1000 | 变倍+ |
| zoom_out | 0x2000 | 变倍- |
| iris_open | 0x4400 | 光圈+ |
| iris_close | 0x4800 | 光圈- |
| focus_near | 0x4100 | 聚焦+ |
| focus_far | 0x4200 | 聚焦- |

**PTZ 命令格式**:

```go
// 8字节命令格式: A5 0F 01 [方向] [速度1] [速度2] [辅助] [校验和]
ptzCmdStr := [8]byte{0xA5, 0x0F, 0x01, 方向, 速度1, 速度2, 辅助, 校验和}
```

### 5.6 录像回放 (record.go)

**录像查询流程**:

```
1. API 调用 GET /api/v1/channels/{id}/records?start=xxx&end=xxx
2. 发送录像查询请求 (Message)
3. 设备返回录像列表
4. 解析并合并连续时间段
5. 返回按日期分组的录像列表
```

**录像回放流程**:

```
1. API 调用 POST /api/v1/channels/{id}/streams
   参数: replay=1&start=xxx&end=xxx
2. 发送 PLAY 请求 (带时间范围)
3. 设备推送历史录像流
4. ZLM 转码并提供播放
5. 客户端播放
```

### 5.7 ZLMediaKit 集成 (zlm.go)

**API 接口封装**:

| 函数 | 说明 |
|------|------|
| `zlmGetMediaList()` | 获取流列表 |
| `zlmGetMediaInfo()` | 获取流信息 |
| `zlmCloseStream()` | 关闭流 |
| `zlmOpenRtpServer()` | 开启 RTP 服务器 |
| `zlmCloseRtpServer()` | 关闭 RTP 服务器 |
| `zlmStartSendRtpPassive()` | 开启被动发送 |
| `zlmStartRecord()` | 开始录制 |
| `zlmStopRecord()` | 停止录制 |

```yaml

mod: release

# 日志级别: trace/debug/info/warn/error

# JWT 配置
jwt:
  token_expire: 7  # Token 有效期（天）

# 媒体服务器配置
media:
  restful: http://127.0.0.1:18080  # ZLM RESTful API
  http: http://127.0.0.1:18080     # ZLM HTTP 地址
  ws: ws://127.0.0.1:18080         # ZLM WebSocket
  rtmp: rtmp://127.0.0.1:1935       # RTMP 地址
  rtsp: rtsp://127.0.0.1:8554       # RTSP 地址
  rtp: http://127.0.0.1:10000       # RTP 推流地址
  secret: your-zlm-secret           # ZLM 密钥

# 流配置
stream:
  hls: 1   # 开启 HLS
  rtmp: 1  # 开启 RTMP

# 录像配置
record:
  filepath: ./recordings     # 录像存储路径
  expire: 7                   # 录像保留天数
  recordmax: 600              # 单个录像最大时长（秒）

# GB28181 配置
gb28181:
  lid: 33010000002000000001   # 系统 ID
  region: 3301000000          # 系统域

  cid: 33010000001318         # 通道 ID 前缀

notify:
  devices_unknown: ""        # 未知设备通知 URL
  devices_active: ""          # 设备活跃通知 URL
  devices_regiest: ""         # 设备注册通知 URL
  channels_active: ""         # 通道活跃通知 URL
```

```
                                                    │

                            │
```

### 10.2 默认角色

| 角色编码 | 角色名称 | 描述 | 权限 |
|----------|----------|------|------|

|------|------|------|

### 10.4 认证流程

```
1. 用户登录 → POST /api/v1/login
2. 验证成功 → 返回 JWT Token（有效期 7 天）
3. 后续请求 → Header 携带 Authorization: Bearer <token>
4. 服务端验证 → Auth 中间件解析 Token
5. 权限检查 → PermissionAuth 中间件检查权限（可选）
```

## 11. GB28181协议实现

### 11.1 支持的 SIP 方法

| 方法 | 说明 | 用途 |
|------|------|------|
| REGISTER | 注册 | 设备注册/注销 |
| INVITE | 邀请 | 直播/回放/对讲 |
| BYE | 挂断 | 停止播放/对讲 |
| MESSAGE | 消息 | 控制指令/查询 |

### 11.2 支持的 GB28181 命令

| 命令类型 | 说明 | 方向 |
|----------|------|------|
| Catalog | 目录查询 | 上级→下级 |
| DeviceInfo | 设备信息查询 | 上级→下级 |
| RecordInfo | 录像查询 | 上级→下级 |
| PTZControl | 云台控制 | 上级→下级 |
| DeviceStatus | 设备状态查询 | 上级→下级 |

### 11.3 SIP 消息头

**必需的 Headers**:

| Header | 说明 |
|--------|------|
| Via | 路由信息，包含 branch、transport |
| From | 源地址，包含 tag |
| To | 目标地址 |
| Call-ID | 呼叫标识（对话唯一） |
| CSeq | 序列号 |
| Contact | 联系方式 |
| Content-Type | 内容类型 (SDP/XML) |

### 11.4 SDP 协商

**直播 INVITE SDP**:

### 11.5 传输模式

## 15. 常见问题

### 15.1 设备无法注册

**问题**: 设备发送 REGISTER 后返回错误

**排查步骤**:

1. 检查 `config.yml` 中 `gb28181.lid` 是否正确
2. 验证设备配置的 SIP 服务器地址和端口
3. 确认设备密码与 `POST /devices/create` 时设置的一致
4. 检查防火墙是否放行 UDP/TCP 55060 端口

### 15.2 播放失败

**问题**: API 返回播放地址但无法播放

**排查步骤**:

1. 确认 ZLMediaKit 正常运行
2. 检查 ZLMediaKit 的 `secret` 与 `config.yml` 一致
3. 确认设备在线且心跳正常
4. 检查网络是否可达（防火墙/NAT）
5. 查看 ZLMediaKit 日志确认是否收到 RTP 流

### 15.3 通道同步失败

**问题**: 调用 `/devices/{id}/channels_sync` 无响应

**排查步骤**:

1. 确认设备状态为已注册 (`regist=true`)
2. 检查设备是否在活跃设备列表中
3. 查看日志确认 SIP MESSAGE 是否发送成功

### 15.4 JWT Token 过期

**问题**: 请求返回认证错误

**解决方案**:

1. 重新登录获取新 Token
2. 检查客户端时间是否正确
3. 确认 `config.yml` 中 `jwt.token_expire` 配置

### 15.5 数据库连接失败

**问题**: 启动时报数据库连接错误

**排查步骤**:

1. 确认 MySQL 服务运行中
2. 验证连接 URL 格式正确
3. 检查用户名密码权限
4. 确认数据库已创建
